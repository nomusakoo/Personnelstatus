# 인원현황 텔레그램 조회봇

화이트리스트에 등록된 경영진만 텔레그램 채팅으로 인원현황 웹앱의 데이터를 조회할 수 있는 봇입니다.
웹앱(`../index.html`)과 별개로 동작하는 독립적인 Node.js 프로젝트이며, 같은 Supabase 프로젝트를
**service_role 키**로 읽기 전용 조회만 합니다 (쓰기 기능 없음).

## 사용 방법 (텔레그램 채팅)

- **이름을 그대로 입력** (예: `홍길동`) → 직급/생년/부서/입사일 요약 (텍스트)
  - 직원 명단과 임원 명단을 모두 검색하며, 동명이인은 전부 나열됩니다.
  - 퇴사한 직원도 검색되며, 이름 옆에 `(퇴사)`로 표시됩니다.
  - 이름 한두 글자를 잘못 입력해도(오타) 가장 비슷한 이름으로 찾아줍니다 (아래 "오타 허용 범위" 참고).
- **`조직도`** → 전체 조직도를 텍스트로 전송
- **직급 또는 직책을 그대로 입력** (예: `과장급`, `팀장`, `본부장`, `사외이사`) → 그 직급/직책에
  해당하는 사람 전체 명단을 본부/팀별로 묶어서 전송
  - 직급(`과장급` 등)은 재직 중인 직원만 대상입니다.
  - 직책(`팀장`/`본부장` 등)은 직원의 직책 항목뿐 아니라, 직원으로 따로 등록되지 않은
    본부장/센터장과 `사외이사`처럼 임원(executives) 쪽에만 있는 직함도 함께 찾아 보여줍니다.
  - 정확히 일치해야 인식됩니다(오타 허용 없음) — `과장급`/`대리급`처럼 끝 글자가 같은
    직급/직책끼리는 오타를 허용하면 서로 헷갈리기 쉽기 때문입니다.
- **본부/부문/팀 이름을 그대로 입력** (예: `경영지원본부`, `SM부문`, `인사노무팀`) → 전체가 아니라 해당
  조직(하위 조직 포함)의 구성원만 좁혀서 텍스트로 전송
  - `SM부문`/`SC부문`처럼 **여러 본부를 묶는 부문**은 `src/constants.js`의 `DIVISION_GROUPS`에
    고정 목록으로 등록돼 있습니다 — divisions/teams 테이블 어디에도 이 상위 그룹을 저장하는
    컬럼이 없기 때문입니다. 부문에 속한 본부가 바뀌면 이 목록을 코드에서 함께 고쳐야 합니다.
  - (참고: 팀의 `center_name`은 이것과 별개로, 한 본부 안에서 팀들을 묶는 용도입니다.)
  - 같은 이름의 조직이 여러 개면 어떤 조직들이 있는지 안내하니 더 구체적으로 입력해 주세요.
  - 조직명도 이름과 마찬가지로 오타를 감안해 가장 비슷한 조직으로 찾아줍니다.
  - **이름이 정확히 일치하는 직원/임원이 있으면 조직명 검색보다 그 사람 정보를 최우선으로
    보여줍니다** (예: `박상민`을 입력했는데 우연히 비슷한 이름의 팀이 있어도, 정확히 일치하는
    사람이 있으면 그 사람 정보만 나옵니다).
  - 조직명도 정확히 일치하는 사람도 아니면 자동으로 대시보드 키워드 → 이름 검색 순으로 처리됩니다.
- **`임원일정`** → 이번 달 임원 일정을 텍스트로 전송
- **`임원일정 10월`** → 지정한 달의 임원 일정을 텍스트로 전송
- **제도 항목명을 그대로 입력** (예: `경조휴가`, `경조금`, `인병휴가 인병휴직`, `가족돌봄휴가 및
  가족돌봄휴직`, `출산관련 휴가 및 휴직`, `해외법인 현황 등`, `연도별 인력현황`, `농협경제지주
  소속`, `해외법인 소속`) → 그 제도의 상세 내용을 텍스트로 전송
  - 외부 연동 프로젝트(`SUPABASE2_*`)의 `hr_policies` 테이블에서 조회합니다 — 외부 연동을
    설정하지 않았다면(`.env`의 `SUPABASE2_URL`/`SUPABASE2_SERVICE_ROLE_KEY` 미설정) 이
    기능은 그냥 동작하지 않고 이름 검색으로 넘어갑니다.
  - `content`가 HTML 문서 형태로 저장돼 있어 태그를 벗겨 평문으로 바꿔 보여줍니다(표/이미지
    등 복잡한 서식은 완벽히 재현되지 않을 수 있습니다. 이미지는 `[이미지 생략]`으로 대체).
  - **"파견현황"처럼 카테고리 이름 자체는 검색되지 않습니다** — `파견현황`은 이미 대시보드
    키워드(현재 파견 인원 수)로 쓰이고 있어서 충돌을 피하려고 뺐습니다. 그 카테고리에 속한
    개별 항목명(`농협경제지주 소속`, `해외법인 소속`)으로 바로 검색해 주세요.
  - 이름/조직명과 마찬가지로 오타를 감안해 가장 비슷한 항목으로 찾아줍니다.
  - 제목 중간에 "및"/"관련"처럼 끼어 있는 연결어는 생략해도 됩니다 — 예를 들어
    "출산관련 휴가 및 휴직"은 `출산휴가`/`출산휴직`만 입력해도 찾아줍니다.
- **대시보드 통계 키워드** (예: `총`/`총인원`/`총원`/`인원`, `입사자`, `퇴사자`, `휴직`, `파견`, `직급별`,
  `직책별`, `본부별`, `사업장별`, `근무직유형`) → 웹앱 대시보드에 있는 것과 같은 통계를 텍스트로 전송
  - `총`/`총인원`/`총원`/`인원` 중 무엇을 입력해도 "현재 총 인원: N명 (등기임원 포함, 사외이사
    제외)"로 답합니다. 등기임원(대표이사/전무이사)은 직원으로 등록돼 있지 않아도 포함하고,
    사외이사는 제외합니다.
  - 정확한 단어를 몰라도 일부 단어만 입력하거나(`사업장`만 입력해도 `사업장별 인원`으로 인식),
    띄어쓰기가 다르거나(`직급 별 인원`), 오타가 한두 글자 있어도(`퇴사쟈`) 인식됩니다.
  - 여러 항목에 걸쳐 모호하면 후보를 안내하니 더 구체적으로 입력해 주세요.
- **`도움말`** (또는 `/start`) → 이름/직급·직책/조직/임원일정/대시보드 통계/제도 등 **유형별로 입력 가능한
  명령어를 정리해서** 다시 보여줌 (외부 연동이 설정돼 있으면 실제 제도 항목명도 카테고리별로 함께 안내)

화이트리스트에 없는 사용자가 메시지를 보내면 "이 봇을 사용할 권한이 없습니다."라고만 답하고,
어떤 명령이 있는지는 알려주지 않습니다.

### 이름/조직명 검색의 오타 허용 범위

이름이나 본부/부문/팀 이름을 검색할 때 다음 순서로 넓혀가며 찾습니다.

1. 정확히 일치하는 이름 (공백 유무, 영문 대소문자는 구분하지 않습니다 — 예: `SM부문`과
   `sm 부문`은 같은 것으로 봅니다)
2. 입력한 글자를 포함하는 이름 (부분일치, 예: `길동` → `홍길동`)
3. 그래도 없으면, 입력한 글자와 가장 비슷한 이름 — 단, **전체 글자 수 기준으로 최소
   30% 이상 일치**해야 하고, 그 조건을 만족하는 후보 중에서도 **가장 비슷한 것만** 찾아줍니다.
   (예: `인사노무팀`을 `인사로무팀`으로 잘못 입력해도 `인사노무팀`을 찾아줍니다. 완전히
   다른 이름/조직명은 30%를 넘지 못해 매칭되지 않습니다.)

가장 비슷한 후보가 여러 개로 동점이면(예: 같은 정도로 비슷한 이름이 두 명) 모두 나열합니다.

### 채팅창 하단 고정 메뉴

채팅창 하단에 `조직도` / `임원일정` / `도움말` 버튼이 항상 떠 있습니다(그래도 어떤 텍스트든
직접 타이핑해서 위 기능을 그대로 쓸 수 있습니다 — 버튼은 자주 쓰는 것만 빠르게 누르기 위한
지름길일 뿐입니다). 이 버튼들은 봇이 보내는 모든 응답에 함께 실려 가는 텔레그램의
"커스텀 키보드"(reply keyboard) 방식이라, 봇 코드가 이미 처리하고 있어 사용자가 따로 설정할
필요는 없습니다. 처음 대화를 시작할 때 안 보인다면 `/start`나 `도움말`을 한 번 입력하면
그때부터 계속 떠 있습니다.

(참고: 텔레그램에는 이것과 별개로 `@BotFather`의 `/setcommands`로 등록하는 "/" 슬래시 명령
메뉴도 있지만, 슬래시 명령 이름은 영문 소문자/숫자/밑줄만 허용되어(`조직도` 같은 한글은 불가)
이 봇에는 맞지 않아 사용하지 않았습니다.)

## 맥미니에서 처음 설치하기

```bash
cd telegram-bot
npm install
cp .env.example .env
# .env를 열어 아래 값을 채운다:
#   TELEGRAM_BOT_TOKEN, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, ALLOWED_TELEGRAM_IDS
```

### 1) 텔레그램 봇 토큰 발급받기

1. 텔레그램에서 `@BotFather` 검색 → 대화 시작
2. `/newbot` 입력 → 안내에 따라 봇 이름/아이디 설정
3. 발급된 토큰(`123456:ABC-...` 형태)을 `.env`의 `TELEGRAM_BOT_TOKEN`에 붙여넣기

### 2) 화이트리스트에 넣을 사람들의 텔레그램 ID 확인하기

1. 각자 텔레그램에서 `@userinfobot`에게 아무 메시지나 보내면 자신의 숫자 ID를 알려줍니다.
2. 그 숫자들을 콤마로 이어서 `.env`의 `ALLOWED_TELEGRAM_IDS`에 넣기 (예: `111111111,222222222`)
3. 인원을 추가/제거할 때는 이 값만 수정하고 봇을 재시작하면 됩니다(아래 pm2 참고). 코드 수정은 필요 없습니다.

### 3) (선택) 외부 연동 임원일정도 함께 보이게 하기

웹앱의 "🔗 외부 임원 일정 연동"과 똑같이, 다른 Supabase 프로젝트의 `hr_exec_events`도 "임원일정"
명령에 함께 표시하고 싶다면 `.env`에 아래 두 값을 채우세요 (둘 다 채워야 활성화됩니다):
```
SUPABASE2_URL=https://그프로젝트.supabase.co
SUPABASE2_SERVICE_ROLE_KEY=그프로젝트의 service_role 키
```
채운 뒤 `pm2 restart telegram-bot`. 외부 연동 일정은 각 줄 끝에 `(외부)`로 구분되어 표시됩니다.
비워두면 지금처럼 기본 임원일정만 나옵니다.

### 4) 수동으로 한 번 실행해서 확인

```bash
npm start
```
텔레그램에서 봇에게 이름/조직도/임원일정을 보내 정상 응답하는지 확인한 뒤 Ctrl+C로 종료합니다.

## 상시 구동 (재부팅/오류에도 계속 실행)

`pm2`로 관리하는 것을 권장합니다 (재부팅 시 자동 재시작까지 한 번에 설정됨):

```bash
npm install -g pm2
pm2 start src/index.js --name telegram-bot
pm2 save
pm2 startup            # 화면에 출력되는 명령을 그대로 한 번 실행 (sudo 필요)
```

이후 관리 명령:
```bash
pm2 restart telegram-bot   # .env 수정(화이트리스트 변경, 토큰 교체 등) 반영 시
pm2 logs telegram-bot      # 로그 확인 (오류 파악용)
pm2 stop telegram-bot      # 중지
```

## 아키텍처 요약

- **롱폴링 방식** — 맥미니에 인바운드 포트를 열거나 공인 도메인/HTTPS 인증서를 준비할 필요가 전혀 없습니다. 봇이 텔레그램 서버로 계속 요청을 보내는 방식이라, 이 기기를 인터넷에 노출시키지 않습니다.
- **조직도/임원일정/대시보드 통계는 텍스트로 전송**됩니다. 텔레그램 메시지 길이 제한(4096자)을 넘으면 자동으로 여러 메시지로 나눠 보냅니다.
- **대시보드 통계**(총인원/입사·퇴사/휴직/파견/직급별/직책별/본부별/사업장별/근무직유형별)는 웹앱(`index.html`)의 대시보드 카드·차트와 같은 계산 방식을 따르되, 텍스트 요약이라 일부 예외 케이스(예: 조직도에 등록되지 않은 본부장/센터장을 임원 목록에서 보완해 총인원에 합산하는 경우)는 반영하지 않아 웹앱과 1~2명 정도 차이가 날 수 있습니다.
- `src/data/repository.js`에는 `select` 쿼리만 있고 insert/update/delete는 없습니다 — 이 봇은 조회 전용입니다.

## 알려진 범위 제한 (v1)

- 화이트리스트는 `.env` 파일 기반입니다. 나중에 경영진 스스로 화이트리스트를 관리하고 싶다면 Supabase 테이블 + 관리자 명령으로 업그레이드할 수 있습니다.
- 이름 검색 결과가 15건을 넘으면 더 구체적으로 입력하라는 안내만 나갑니다 (전체 나열 안 함).

## 테스트

```bash
npm test              # 목업 데이터 기반 단위 테스트 (Supabase/텔레그램 연결 불필요)
```

실제 텔레그램 왕복 테스트(화이트리스트 통과/거부 포함)는 위 설정을 마친 뒤 직접 메시지를 보내
확인해야 합니다 — 이 저장소의 자동화 테스트만으로는 검증할 수 없는 부분입니다.
