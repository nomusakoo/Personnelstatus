# 인원현황 텔레그램 조회봇

화이트리스트에 등록된 경영진만 텔레그램 채팅으로 인원현황 웹앱의 데이터를 조회할 수 있는 봇입니다.
웹앱(`../index.html`)과 별개로 동작하는 독립적인 Node.js 프로젝트이며, 같은 Supabase 프로젝트를
**service_role 키**로 읽기 전용 조회만 합니다 (쓰기 기능 없음).

## 사용 방법 (텔레그램 채팅)

- **이름을 그대로 입력** (예: `홍길동`) → 직급/생년/부서/입사일 요약 (텍스트)
  - 직원 명단과 임원 명단을 모두 검색하며, 동명이인은 전부 나열됩니다.
  - 퇴사한 직원도 검색되며, 이름 옆에 `(퇴사)`로 표시됩니다.
- **`조직도`** → 현재 조직도를 텍스트로 전송
- **`임원일정`** → 이번 달 임원 일정을 텍스트로 전송
- **`임원일정 10월`** → 지정한 달의 임원 일정을 텍스트로 전송

화이트리스트에 없는 사용자가 메시지를 보내면 "이 봇을 사용할 권한이 없습니다."라고만 답하고,
어떤 명령이 있는지는 알려주지 않습니다.

## 맥미니에서 처음 설치하기

```bash
cd telegram-bot
npm install
cp .env.example .env
# .env를 열어 아래 값을 채운다:
#   TELEGRAM_BOT_TOKEN, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, ALLOWED_TELEGRAM_IDS
```

### 1) 텔레그램 봇 토큰 발급받기

1. 텔레그램에서 `@BotFather` 검색 → 대화 시작
2. `/newbot` 입력 → 안내에 따라 봇 이름/아이디 설정
3. 발급된 토큰(`123456:ABC-...` 형태)을 `.env`의 `TELEGRAM_BOT_TOKEN`에 붙여넣기

### 2) 화이트리스트에 넣을 사람들의 텔레그램 ID 확인하기

1. 각자 텔레그램에서 `@userinfobot`에게 아무 메시지나 보내면 자신의 숫자 ID를 알려줍니다.
2. 그 숫자들을 콤마로 이어서 `.env`의 `ALLOWED_TELEGRAM_IDS`에 넣기 (예: `111111111,222222222`)
3. 인원을 추가/제거할 때는 이 값만 수정하고 봇을 재시작하면 됩니다(아래 pm2 참고). 코드 수정은 필요 없습니다.

### 3) (선택) 외부 연동 임원일정도 함께 보이게 하기

웹앱의 "🔗 외부 임원 일정 연동"과 똑같이, 다른 Supabase 프로젝트의 `hr_exec_events`도 "임원일정"
명령에 함께 표시하고 싶다면 `.env`에 아래 두 값을 채우세요 (둘 다 채워야 활성화됩니다):
```
SUPABASE2_URL=https://그프로젝트.supabase.co
SUPABASE2_SERVICE_ROLE_KEY=그프로젝트의 service_role 키
```
채운 뒤 `pm2 restart telegram-bot`. 외부 연동 일정은 각 줄 끝에 `(외부)`로 구분되어 표시됩니다.
비워두면 지금처럼 기본 임원일정만 나옵니다.

### 4) 수동으로 한 번 실행해서 확인

```bash
npm start
```
텔레그램에서 봇에게 이름/조직도/임원일정을 보내 정상 응답하는지 확인한 뒤 Ctrl+C로 종료합니다.

## 상시 구동 (재부팅/오류에도 계속 실행)

`pm2`로 관리하는 것을 권장합니다 (재부팅 시 자동 재시작까지 한 번에 설정됨):

```bash
npm install -g pm2
pm2 start src/index.js --name telegram-bot
pm2 save
pm2 startup            # 화면에 출력되는 명령을 그대로 한 번 실행 (sudo 필요)
```

이후 관리 명령:
```bash
pm2 restart telegram-bot   # .env 수정(화이트리스트 변경, 토큰 교체 등) 반영 시
pm2 logs telegram-bot      # 로그 확인 (오류 파악용)
pm2 stop telegram-bot      # 중지
```

## 아키텍처 요약

- **롱폴링 방식** — 맥미니에 인바운드 포트를 열거나 공인 도메인/HTTPS 인증서를 준비할 필요가 전혀 없습니다. 봇이 텔레그램 서버로 계속 요청을 보내는 방식이라, 이 기기를 인터넷에 노출시키지 않습니다.
- **조직도/임원일정은 텍스트로 전송**됩니다. 텔레그램 메시지 길이 제한(4096자)을 넘으면 자동으로 여러 메시지로 나눠 보냅니다.
- `src/data/repository.js`에는 `select` 쿼리만 있고 insert/update/delete는 없습니다 — 이 봇은 조회 전용입니다.

## 알려진 범위 제한 (v1)

- 화이트리스트는 `.env` 파일 기반입니다. 나중에 경영진 스스로 화이트리스트를 관리하고 싶다면 Supabase 테이블 + 관리자 명령으로 업그레이드할 수 있습니다.
- 이름 검색 결과가 15건을 넘으면 더 구체적으로 입력하라는 안내만 나갑니다 (전체 나열 안 함).

## 테스트

```bash
npm test              # 목업 데이터 기반 단위 테스트 (Supabase/텔레그램 연결 불필요)
```

실제 텔레그램 왕복 테스트(화이트리스트 통과/거부 포함)는 위 설정을 마친 뒤 직접 메시지를 보내
확인해야 합니다 — 이 저장소의 자동화 테스트만으로는 검증할 수 없는 부분입니다.
